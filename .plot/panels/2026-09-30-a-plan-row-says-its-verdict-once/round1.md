## Findings

1. **The diagnosis is right for NOT STARTED.** The plan-group site (`AgentList.tsx:1489-1582`) sets `foldable = showsSliceFold(group)`, and `showsSliceFold` returns `groupBySlice(group.rows).length > 1` (`sections.ts:688-697`), so a one-slice plan gets `expanded = null` and its slice rows render unconditionally (`{(expanded === null || expanded) && (<ul data-slice-list…>`). The SliceRow there receives no `soleRow`, so its status is the verdict (`tuple-row.ts:1508-1516`). The plan row's aside also reads `1 slice, first eligible` there (`sliceSummaryFor`, `sections.ts:585-600`). In NOT STARTED the removal loses nothing.

2. **The design's premise "The slice row renders it for every plan, so removing it from the plan row loses nothing a reader could see before" is false in the `planHeads` sections (WAITING ON YOU, QUIET, DONE).** At the `planHeads` site the SliceRow receives `soleRow={wg.rows.length > 1 ? undefined : wg.rows[0]}` (`AgentList.tsx` in the `sliceGroupsFor(...).map` block after `:2019`). `tupleFromSlice` prints `facts.soleStatus` first, and `soleStatus = soleRowStatus(soleRow)` (`rows.tsx:1130`), which returns `prStatus(row.pr)` (`stuck.ts:104-113`): `green`, `CI running`, `checks failing`, `no checks`, `conflicts`, `closed`. The verdict only reaches the slice row when that word is empty (a merged PR, which is the measured #1061 case). `statusAttr` is likewise `data-pr-state` and not `data-verdict` whenever `soleRow?.pr` exists (`rows.tsx:1320-1324`). So for a one-slice plan with an open PR in WAITING ON YOU, the slice row shows `green` and no verdict; after the change the verdict appears on no row.

3. **A one-slice plan head outside NOT STARTED is collapsible, and collapsed it shows the plan row without the slice row.** The `planHeads` site passes `expanded={… sliceGroupsFor(...).length > 1 ? openPlans.has('open:…') : !openPlans.has('shut:…')}` and always passes `onToggle` (`AgentList.tsx:1881-1891`); `PlanRow` computes `foldable = expanded !== null` (`rows.tsx:585`) and renders the `data-slice-toggle` button. The slice list renders only when that same expression is true (`{(!planHeads || hasExceptions(...) || (... : !openPlans.has('shut:…'))) && (<ul …`). A reader who shuts a one-slice plan in WAITING ON YOU or DONE sees only the plan row; today it carries the verdict, after the change it carries the phase and, for a quiet PR, nothing else (`planPrAggregate` returns null for `green`/`none`/`unknown`/`closed`/merged, `tuple-row.ts:458-475`). The plan does not name this case.

4. **The replacement repeats a different word instead.** For a one-slice plan with a `failing` or `conflicts` PR in a `planHeads` section, the plan row will print `checks failing` (the fold, count 1) and the slice row prints `checks failing` (`soleRowStatus`). The plan's title claim — the status is said once — moves the duplication from the verdict to the PR word for exactly the one-slice case. This is what Done-when 1 asks for ("holds what a two-slice plan row holds"), so it is a stated choice, but the Motivation argues against stating one fact twice and the plan should say it accepts this for the fold's collapsed-plan purpose.

5. **Q2, an eligible one-slice plan with no PR:** `planPrAggregate` returns null when no branch carries `conflicts`/`failing`/`pending` ("a plan of unstarted branches folds to nothing", `tuple-row.ts` docstring above `:458`). The plan row then shows only its phase where it showed `eligible`. In NOT STARTED this is no loss (finding 1: slice row always renders its verdict, and the aside says `first eligible`). No change needed for this case.

6. **No test asserts `data-sole-wave-verdict` or the sole-slice verdict on the plan row.** `git grep -n -e "sole-wave-verdict" -e "soleSlice" -e "sole slice" origin/main -- packages` outside the two source files returns only `menus.tsx` (the action gate), `test/catalogue/states.ts:472` (a comment about `PlanActions`' render gate) and domain pulse tests. `git grep -i -e sole-wave -e soleWave origin/main -- packages/board/test` returns only `plan-row-slice-actions.browser.test.ts` (Start-work, not the verdict) and a fixture comment. The Slices line's "the browser tests that assert the sole-slice verdict on the plan row" names tests that do not exist; the new browser test in Done-when 1 is the only coverage. `folded-plan-pr-fold.browser.test.ts` fixtures carry no `slices`, so `soleSlice` is null there and it is unaffected.

7. **Q4, the Start-work gate is intact.** `PlanActions soleSlice={soleSlice?.verdict === 'eligible' && card && dispatch ? … : undefined}` (`rows.tsx:877-881`) is separate from `statusExtra` (`rows.tsx:751-798`). Removing the `soleSlice?.verdict ?` arm does not touch it. The NOT STARTED slice row withholds `card`/`dispatch` for a one-slice plan (`card={oneSlice ? null : …}`), so the plan row stays the only carrier of Start work, as the plan says.

8. **More comments go false than the one docstring the plan names.** Besides the `soleSlice` docstring (`rows.tsx:526-534`), these state the old rule: the `dispatch` prop docstring ("`soleSlice` hides the slice row", `rows.tsx:539`), the `statusExtra` comment ("the slice row is suppressed, so this is the only place the verdict appears", `rows.tsx:746-750`), the rounds-badge comment ("before the verdict/PR fold", `rows.tsx:753`), both call sites ("A ONE-SLICE plan shows its slice's verdict on this row instead of nesting a slice row beneath it", `AgentList.tsx:1580-1581` and `:1908-1909`), and both "the verdict migrated to the plan row" comments (`AgentList.tsx:1645-1648`, `:2019-2023`). The `plan-rounds-badge.browser.test.ts:26-28` header also says the badge "does not evict the verdict". Done-when 4 covers only the first.

9. **Q5, testability.** Done-when 1, 3 and 4 are testable. Done-when 2, "The slice row of that one-slice plan still renders its verdict", is false as written for any section where the slice row has a `soleRow` with a non-empty `prStatus` (finding 2); a test would pass only if its fixture uses NOT STARTED or a merged PR, and would fail for WAITING ON YOU with a green PR.

## What the plan must change

1. Replace the Design sentence "The slice row renders it for every plan, so removing it from the plan row loses nothing" with the true scope: NOT STARTED always renders the slice row with its verdict; in WAITING ON YOU, QUIET and DONE a one-branch slice row shows its PR word (`soleRowStatus`) and shows the verdict only when that word is empty. State that the verdict is then dropped for one-slice plans with an open PR, and why that is acceptable (e.g. `eligible` beside an open PR says nothing), or keep it there.
2. Name the collapsed one-slice plan head in the `planHeads` sections (`shut:` override) and decide it: accept that the collapsed row shows only phase and fold, or keep the verdict when `expanded === false`.
3. Scope Done-when 2 to where it holds (NOT STARTED, and a merged-PR slice elsewhere), or rewrite it to "the verdict or the PR word the slice row shows today is unchanged", so a test can pass on every section fixture.
4. State that a one-slice plan with a `failing`/`conflicts` PR now prints that word on both the plan row and the slice row, and that this is accepted.
5. Extend Done-when 4 to every comment listed in finding 8, and fix the Slices line: no existing test asserts the plan-row verdict, so the slice adds the test rather than rewriting one.
