# Cost juror, round 3 — the-fleet-writes-the-design

Position: amend

The revision applies every round-2 cost amendment and D34. The restart now passes `halted` once and its success lifts the halt, success means fleetd opened a draft PR, a crashed run and a stale claim settle from the store, `specRow` is a domain rule with unit tests and one browser test, the shared parts move into `fleet-run.ts` instead of being copied, and the cost line counts one host read and three host writes. Declining a separate `Design bound` has a stated reason. One new cost defect remains, and it is in the new text: `specStart` tests `declined` and `host-unknown` before `halted`, `stopped`, `waiting` and the slot refusals, so its `prState` reading must exist on every pass for every Design plan whose spec is empty and whose ref is absent. A plan that the fleet stopped after 3 failures has its ref deleted, so it reads `absent` forever, and fleetd asks the host about it once per pass (60 s) until a person acts: about 1440 host calls a day per stopped plan, and the same while the machine has no free slot. The cost line says "one host read" per run, which is true per started run and false per pass. The fix is an order change in one rule. Two smaller wording and scope defects follow. Amend, then proceed.

## Findings

1. **high — the `prState` read happens on every pass, not once per run, for a plan that waits, stops or halts.** `specStart` refuses in the order `off`, `running`, `declined`, `host-unknown`, `halted`, `stopped`, `waiting`, `queue-unread`, `no-free-agent`, `starved` (plan `:52`). `host-unknown` is a refusal of the rule, so the host answer is one of its readings, and the plan says fleetd reads `host.prState('idea/<slug>-spec')` "before it claims" (plan `:64`) with no condition on the local refusals. `designWork` answers `write-spec` for every Design plan with an empty spec and an `absent` ref (plan `:51`). After a `spec-empty`, `no-commit` or `stale-claim` failure the ref is deleted (plan `:78-79`, `:87`), so a plan in `waiting`, `stopped` or `halted` reads `absent` on every later pass and pays one `prState` call each time. The `declined` mark stops the reads only after a closed PR (plan `:64`); a stopped plan has no PR, so nothing ever writes the mark. The same holds on a busy machine: `no-free-agent` and `starved` come after `host-unknown`, so a Design plan that waits for a slot costs one host call per pass. `verifyStart` has no host reading at all (`packages/domain/src/rules/auto-verify.ts:164-179`), so this cost is new and has no precedent to copy. This is the cheaper behaviour and it is correct, but Changelog item 5 (plan `:20`) and the cost line (plan `:102`, "at most two automatic retries per plan") state a retry that this arm never makes. The Acceptance line for the settlement table (plan `:146`) tests that the ref is kept and does not test that no retry follows. A reader who sizes the Opus spend from the Changelog counts three runs where one run happens.

A plan-level row in *Working* is therefore new board code in slice 4, not reuse. The slice and its browser test are still small; the scope is understated.
