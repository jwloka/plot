# Cost lens — the-phases-are-declared

Position: amend

## Summary

The plan's direction follows D1, D2, D3 and D12, and its domain citations are mostly true. The cost lens finds three problems. First, the plan does not count the board code that branches on literal phase names, and one of those sites removes the Approve and Commission controls from every Draft plan when the default map moves Draft to Design. Second, the first slice already changes what the board renders, so the board's churn lands in wave 1 and not in wave 2 as the slicing says. Third, the *Needs design* slice names one gate surface (`owningCommand`) and leaves out the four that actually admit or refuse the write. None of these needs a decision to change. Each needs the plan to name the work, so the operator and the implementing agent can see the cost before approval.

## Findings

1. **Unresolved. `isDraft` reads the column, and the default map empties it.** `packages/board/src/app/components/PlanCard.tsx:83-85` returns `card.phase === 'Discovery'`, and its comment (`:66-70`) says "`Discovery` IS Draft on this board". `packages/board/src/app/lib/agent-rows/menus.tsx:1464-1466` gates `canApprove` and `canCommission` on `isDraft(card)`. With `DEFAULT_PHASE_MAP`, a Draft plan reads in Design, so `isDraft` is false for every plan and the Approve control disappears. `PlanCard.tsx:24-30` records the same failure mode once before: "the `Start work` button vanished … and nine browser tests timed out". The plan names neither predicate. The *Needs design* button ("on a Draft plan's card") needs a Draft test too, and a column test cannot tell `draft` from `design` once both share Design. Fix: the card must carry the plan state, and `isDraft` must read it.
2. **Unresolved. Literal phase names in the board are not counted.** Besides `isDraft`: `PlanCard.tsx:41` and `:63` (`'Development'` for Ready and Approved; `menus.tsx:1204` dispatch gate), `Board.tsx:224` (`'Testing'` checklist), `App.tsx:877` (`'Released'`), `server/board.ts:1165-1177` (`phaseDateOf`, a `switch` over the five names), `server/board.ts:2204` (`'Development'`), `server/fleet.ts:5842` (an `idea/` branch reads `'Discovery'`, which under the default map is the wrong column for a Draft plan's branch), and `server/mock-fleet.ts` (13 literals). With a custom map these all fail silently, because the wire type becomes a string and TypeScript loses exhaustiveness. The plan's sentence "The wire field typed `z.enum(BOARD_PHASES)` becomes a string" names one field; `schema.ts:425` (`CardSchema`) and `schema.ts:736` (`ColumnSchema`) are two.
3. **Unresolved. The board churn sits in wave 1.** Slice 1 moves the callers of `toBoardPhase`, `storyPhase` and `rowPhase` to the new rules. Those callers are in the board: `server/board.ts`, `server/fleet.ts`, `contract/schema.ts`, `app/components/PlanCard.tsx` (grep for `toBoardPhase` under `packages/board/src`). With the default map, slice 1 therefore moves every Draft card to Design and every story to Discovery. Every board test that asserts a Draft in Discovery breaks in slice 1: 27 test files hold a `'Discovery'` literal (24 under `packages/board/test`, 2 under `packages/domain/test`, 1 catalogue), 21 of them browser tests under `test/integration/`. The plan says slice 2 is where "the board draws the map". Either slice 1 carries the board fixture changes and the `isDraft` fix, or slice 1 keeps today's mapping behind the new API and slice 2 switches the default. The plan must say which.
4. **Unresolved. The *Needs design* slice misses its gate surfaces.** `owningCommand` (`rules/state-transition.ts:93-105`) only writes the refusal text. What admits a commit is a receipt. The action words are a closed list in three places: `ControllerAction = 'dispatch' | 'approve' | 'deliver' | 'release'` (`rules/controller-gate.ts:11`), the regex `/plot-(dispatch|approve|deliver)/` (`controller-gate.ts:50`), and `_action_of` in `skills/plot/scripts/plot-state-receipt.sh:173-180`. The sentence "`owningCommand` names the action for `design`, so the state gate admits the write when the receipt matches" puts the cause on the wrong function. Adding an arm to `plot-state-receipt.sh` adds shell lines, and `scripts/check-shell-lines.sh` refuses a net increase of shipped shell. The plan does not mention that cost. The `owningCommand` default text (`:104`) also states "Draft > Approved > Delivered > Released", which the prose slice must change and does not list.
5. **Unresolved. Two Motivation claims are false.** `DESIGN-plan.md` §4 (`docs/stories/the-master-agent-holds-the-fleet/DESIGN-plan.md:688-830`) does not describe four phases: it describes seven states (`:692`) and already names the five agentic phases as the board's columns (`:750-755`). `DESIGN-story.md` §4 (`:562-620`) describes six story statuses and no phases. The prose slice's scope for those two files is smaller than stated, and the plan must drop or restate them. The other prose citations are true: `skills/plot/SKILL.md:170-182` (four plan phases), `:266` ("4 columns (Draft / Approved / Delivered / Released)"), `skills/plot/MANIFESTO.md:99-109` and `:148`.
6. **Resolved, true.** `entities/workflow.ts:35` (`BOARD_PHASES`), `:62` (`PHASE_LEADERSHIP`), `:143` (`PHASE_WORKFLOWS`), `:166` (`phaseOf`); `rules/phase.ts:41` (`draft` to Discovery), `:72` (`storyPhase` over five phases), `:99` (`rowPhase`); `server/board.ts:2082-2117` (the auto-bump via `toBoardPhase('delivered')` at `:2115`); `plot-plan-meta.sh:245-246` (`design_raw`); `ports/plan-store.ts:131` (`config(key, fallback)`); `packages/fleet/src` holds no `BOARD_PHASES`, `toBoardPhase`, `storyPhase` or `rowPhase` today (one comment word "Phase" at `shared/queue-reading.ts:325`). The code under `packages/` is identical to `75f093cb9` (`git diff --stat` empty).
7. **Unresolved, minor. The "fleet reads no phase name" check is scoped too narrowly.** The grep names `packages/fleet/src`, but `packages/board/src/server/fleet.ts:5842` writes a phase name for the fleet view. D12 is about the fleet process, so this is not a contradiction. The plan should still list `server/fleet.ts:5842` in slice 1 or 2, because the default map makes its answer wrong.
8. **Cost not stated.** The plan names no tests per slice. Domain: `test/phase.test.ts` (176 lines) and `test/workflow.test.ts` (243 lines) assert the current mapping. Board: `test/unit/phases.test.ts`, `swimlanes.test.ts`, `fleet.test.ts`, `classifier-is-total.test.ts`, `merged-slices-reach-testing.test.ts` import the replaced symbols. Most of the 27 `'Discovery'` files run under `pnpm run test:board`, which starts browser tests, so the plan buys several CI rounds on the board suite. One sentence per slice that names the test files it changes lets the operator size the review.

## What should change before approval

- **Design › The board:** add a paragraph that `Card` carries the plan state and that `isDraft`, `isApproved`, `isReadyToStart`, `phaseDateOf`, `Board.tsx:224`, `App.tsx:877` and `server/fleet.ts:5842` read a state or a map membership instead of a phase literal. Name both `schema.ts:425` and `:736`.
- **Slices › The declared map:** state whether slice 1 changes the rendered mapping. If it does, move the board fixture changes and the `isDraft` fix into slice 1. If it does not, say that slice 1 keeps today's draft-to-Discovery mapping and slice 2 switches the default.
- **Design › Needs design:** replace "`owningCommand` names the action … so the state gate admits the write" with the list `ControllerAction` (`controller-gate.ts:11`, `:50`), `_action_of` (`plot-state-receipt.sh:173-180`), and the `owningCommand` text (`state-transition.ts:104`), and name the `check-shell-lines.sh` offset.
- **Motivation, last bullet:** drop `DESIGN-plan.md` §4 and `DESIGN-story.md` §4, or restate what they say; trim the prose slice to match.
- **Each slice:** add the test files it changes, as counted in finding 8.
