## Findings

1. **medium — Success is "the branch reads `work`", which does not prove that a PR exists, and a closed PR restarts the run with no bound.** Plan `:58` says that a run which leaves the branch at `work` succeeded. A run that pushes one commit and dies before `plot-host.sh pr-create` therefore reads as success. Then `designWork` answers `none` (`specRef` is `work`), and `restart` (`:61`) deletes a `work` ref only "when the spec PR is closed unmerged". With no PR at all, neither rule applies, and the plan stays with no spec and no way out. In the other direction, when a person closes the spec PR and the host deletes its head branch, `specRef` reads `absent` and the spec is still empty. The next pass then starts a new Opus run. That run counts as a success, not a failure, so the stop-after-3 rule never applies. A person who rejects a spec therefore gets it written again on the next pass. Checked: `ClaimAnswer` at `packages/domain/src/rules/claim.ts:15`, plan `:46`, `:58`, `:61`. The Acceptance (`:98`, `:99`) tests neither case.
