# Deliverable lens: the-phases-are-declared

Position: amend

The plan's citations hold. Its slices name real artifacts. Two deliverable gaps block approval as written. First, Changelog bullet 2 promises a board that no slice in this plan builds. Second, the first slice cannot land alone without either shipping that bullet early or leaving the wire schema half-moved. Both gaps are text changes, not redesigns.

## Answers to the rubric

1. **Factual claims.** Every file:line I checked is correct on this branch (list under Evidence). Three claims are true in letter but mislead: the `storyPhase` claim (finding F1), the fleet grep claim (F6) and the `owningCommand` mechanism (F7).
2. **Summary and Changelog.** Bullets 1, 3 and 4 each have a slice that builds them. Bullet 2 ("Discovery holds only stories") has no slice that puts a story into a board column (F1). The prose slice has no bullet (F4).
3. **Through the deliverable lens.** The first slice's boundary is unclear (F2). Several `BOARD_PHASES` readers are named by no slice (F3). `rowPhase` gets a reading that its callers do not have (F5).
4. **Changes.** See the "Change:" line in each finding.

## Findings

- **F1 (unresolved). No slice puts a story into a column, so bullet 2 ships an empty Discovery column.** `storyPhase` has no production caller. `grep -w storyPhase packages/*/src` returns only its definition at `packages/domain/src/rules/phase.ts:72`. The only other hits are tests (`packages/domain/test/phase.test.ts:153-173`, `packages/domain/test/workflow.test.ts:95,150,159`). The board's columns hold plan cards only: `packages/board/src/server/board.ts:2252` builds `columns` from `cards`, and `ColumnSchema` holds `z.array(CardSchema)` (`packages/board/src/contract/schema.ts:735-737`). Stories are swimlane rows, not cards (`packages/board/src/app/components/Swimlanes.tsx:39`). So the Motivation line "`storyPhase` spreads the six story statuses over all five phases" describes a function that nothing renders. The story's "Why Now" claim that this "spreads stories over all five columns" is false on this branch. With `DEFAULT_PHASE_MAP`, Draft plans leave Discovery, so the plans board shows an empty Discovery column. That column stays empty until `tickets-and-stories-have-lanes` (Phase 4) builds a Discovery view. The new `phaseOfStory` is also a deliverable with no consumer in this plan. Change: rewrite bullet 2 as "With the default phases, no plan reads in Discovery, and a Draft plan reads in the Design column". Correct the Motivation line to say that `storyPhase` has no production caller. Then do one of two things. (a) Move `phaseOfStory` to the plan that first calls it. (b) Keep `phaseOfStory` in slice 1 and say that its first caller is `tickets-and-stories-have-lanes`. The plan must also say what the Discovery column shows in the interval: hidden, or empty and labelled.
- **F2 (unresolved). The first slice cannot land on its own as written.** Slice 1 says "`toBoardPhase`, `storyPhase` and `rowPhase` callers move to the new rules; `BOARD_PHASES` and `PHASE_WORKFLOWS` stop being the source". The callers are board code: `board.ts:2082` and `:2115` (`toBoardPhase`), `board.ts:2079` and `packages/board/src/server/fleet.ts:2269,5463` (`rowPhase`). Slice 1 has no map to pass except `DEFAULT_PHASE_MAP`, because the board reads the key only in slice 2. That choice moves Draft plans to Design in slice 1, so bullet 2 ships in slice 1, and its `builds:` annotation does not say so. The tests that assert today's mapping also move in slice 1, for example `packages/domain/test/phase.test.ts:157-161`. If `BOARD_PHASES` "stops being the source" in slice 1, then the wire schema's `z.enum(BOARD_PHASES)` (`schema.ts:425,736,2486`) and the exported `Phase` type (`packages/domain/src/entities/workflow.ts:40`) must change in slice 1 as well. The plan gives that schema work to slice 2 ("the wire schema names a declared phase"). Change: in slice 1, state that board callers pass `DEFAULT_PHASE_MAP` and that the Draft-to-Design move ships here. State also that `BOARD_PHASES` and `Phase` remain as the default map's names until slice 2 widens the wire field. Add "the Draft-in-Design reading" to slice 1's `builds:` annotation.
- **F3 (unresolved). Some `BOARD_PHASES` readers are named by no slice.** Slice 2 names only `Board.tsx` and `Swimlanes.tsx`. These readers also use the constant list: `packages/board/src/app/components/StoryModal.tsx:84` (`plansInStory` sorts by `BOARD_PHASES`), `packages/domain/src/entities/workflow.ts:80` (`phaseOrder`) and `:178-186` (the `WORKFLOW` record), and `packages/board/src/contract/schema.ts:191-195` (the re-export and the `PHASE_LEADERSHIP` typing). Under a declared map that reorders or renames phases, `plansInStory` sorts against the default order, and `phaseOrder` answers `-1` for a declared name. Change: add `StoryModal.tsx`, `phaseOrder` and `WORKFLOW` to slice 2's text, or to slice 1's text for the domain items.
- **F4 (unresolved). The prose slice has no Changelog bullet, and it omits the `AGENTS.md` mirror.** `docs/the-prose-names-the-declared-phases` builds "the five-phase prose", and no Changelog bullet covers it. This slice edits `CLAUDE.md` *Phase Guardrails*. `AGENTS.md` is generated from `CLAUDE.md`, and `./scripts/check-agents-md.sh` is in the `**` local checks, so the slice fails that gate unless it runs `--write`. Slice 1 names this step, and the prose slice does not. Change: add a bullet such as "Plot's docs, `/plot` and the manifesto describe the declared phases and the five-phase default." Add "`AGENTS.md` follows" to the prose slice.
- **F5 (unresolved). The design changes the `rowPhase` inputs.** The Design section says "`rowPhase` composes `phaseOfPlan`. The readings are the plan state and `planStatus`." Today `rowPhase(planPhase, state)` takes the plan's state and a branch state, with no `planStatus` (`packages/domain/src/rules/phase.ts:99-104`). Its caller at `packages/board/src/server/fleet.ts:5463` passes `rowPhase(plan.phase, b.state)` and has no `planStatus`. If `phaseOfPlan` applies the `deliverable` reading, the board's per-branch rows begin to auto-bump. Today only cards do (`board.ts:2115`). Change: say that `rowPhase` passes no `planStatus`, so rows do not bump. Or name the row bump as a behaviour change and give it a slice.
- **F6 (resolved by wording). The fleet grep proves nothing that the slice builds.** "A grep for `BOARD_PHASES`, `toBoardPhase` and `storyPhase` under `packages/fleet/src` returns zero matches after the first slice." The same grep returns zero matches today (one unrelated comment hit at `packages/fleet/src/shared/queue-reading.ts:325` for a broader pattern). The claim is true, but it is not an acceptance check. Change: write "returns zero matches today and after the first slice". Or name the real fleet-side reader, `packages/board/src/server/fleet.ts`, which calls `rowPhase` at `:2269` and `:5463`.
- **F7 (resolved by wording). `owningCommand` does not admit a write.** The Design section says "`owningCommand` names the action for `design`, so the state gate admits the write when the receipt matches". `owningCommand` (`packages/domain/src/rules/state-transition.ts:93-105`) only builds the refusal text. A receipt keyed by path and value admits the write (`skills/plot/scripts/plot-state-receipt.sh:6-7`). The slice still has to make the bundle call the receipt writer, and the plan names that ("both leave a receipt"). Change: write "the receipt admits the write, and `owningCommand` names `/plot-needs-design` in the refusal for `design`".
- **F8 (note). Wave order is valid but not tight.** `feature/the-idea-asks-about-design` reads nothing from wave 1 or from the board slice. `toBoardPhase('design')` already answers Design (`phase.ts:45-46`), and a creation passes the gate (`state-transition.ts:121`). It can land in wave 1. Sibling waits match the branch names: `design-work-proves-the-path` waits on `feature/the-phases-are-a-declaration`, and `the-board-has-three-tabs` waits on `feature/the-board-draws-the-declared-phases`. No change is required.
- **F9 (note). Unattended `/plot-idea` has no answer for the design question.** `skills/plot-idea/SKILL.md:82` has a *Batch Mode*, and the board's `idea.ts` runs `/plot-idea` unattended through `Idea command` (`packages/board/src/server/idea.ts:65`). The plan says that a Small model asks. It does not say what an unattended run writes when nobody can answer. D3 says the fleet never decides design. Change (suggested): state that an unattended run writes `State: Draft` and leaves the decision to *Needs design*.
