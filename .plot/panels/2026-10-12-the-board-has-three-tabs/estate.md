# Estate juror: the-board-has-three-tabs

Position: amend

I read `main` at `316d3de0e`. Most of the line references in the plan hold. One claim that carries weight is false: the board's *Waiting on you* tickets do not pass through `issueOf` or `trackerReads`. `refreshIssues` in `packages/board/src/server/fleet.ts` parses the `issue-list` JSON by hand into `IssueRowSchema`. The `feature/an-issue-names-its-assignee` slice as written therefore gives the Delivery tab no assignee, and `waitingTickets` filters on a field the board never receives. Three other parts would build again what the estate already holds. *Only my work* already filters PRs by author and plans by `Assignee:` through `rules/ownership.ts`. *Active sprint* is the existing sprint multiselect with every option selected, because `fleet.sprints` already holds only the Active sprints. `planningColumns(map, …)` needs a phase map that the client does not receive, because the server builds the columns with `phaseColumns`. The redirects, the tab rule and the `People` grammar are sound as written.

## Findings

1. **high: the assignee does not reach the board through `issueOf`.** `packages/board/src/server/fleet.ts:1473` `refreshIssues` calls `scriptsFor(opts).hostSaid(['issue-list', …])` (`:1492`) and projects each line by hand into `{number,title,url,createdAt,status,statusCategory}` (`:1536-1561`). The comment there warns that "a key it does not name is a key the board never shows". The wire row is `IssueRowSchema` (`packages/board/src/contract/schema.ts:3368`), and its doc (`:3321`) says "No labels, no assignee". `trackerReads`/`issueOf` (`packages/domain/src/adapters/tracker/tracker-shell.ts:46`, `:120`) are used only by `tracker-github.ts` and `tracker-jira.ts`, and nothing in `packages/board/src` calls them. The plan's sentence "`trackerReads` serves … alike, so a matched reader … also sees their tickets" is therefore false today. It holds only after the issue index of `tickets-and-stories-have-lanes` moves the board onto the port, and `feature/the-fleet-indexes-issues` carries only its claim commit (`930cb07d7`). Checked with `grep -rln "trackerReads\|\.issueList("` over `packages/*/src` and by reading `fleet.ts:1460-1600`.
2. **medium: *Only my work* already covers PRs and plans, and the rule that would gain tickets is `ownership`, not a new resolver.** `rowsForReader` (`packages/board/src/app/lib/agent-rows/mine-filter.ts:135`) filters PRs by author. `boardForReader` (`:162`) filters plan cards by `Assignee:`. Both call `isMine` (`packages/domain/src/rules/ownership.ts:135`), whose `OwnedRow` names `{ kind: 'other' }` for "an issue, a build, or a branch with no PR. None carries an owner" (`:38-45`). The plan names neither `ownership.ts` nor `isMine`. It proposes `assigneeHandle` in `entities/person.ts` as a second resolver beside `prOwnership` and `planOwnership`, which already resolve a handle through `resolvePerson` (`ownership.ts:68-91`). The two also disagree. `isMine` keeps an `unknown` row (`:126-135`), but the plan says "a ticket with no assignee is not the reader's". That divergence is legitimate for the inbox default, but the plan must state it against `ownership`. Otherwise *Only my work* and *Waiting on you* give two answers for one ticket.
3. **medium: branches and builds have no owner field to filter on.** `AgentRow` carries `author` only from a PR (`schema.ts:324-331`, `:2674-2677`), and `ownership.ts:21` says `gitEmail` is "Never compared against a PR author". The plan says *Only my work* filters "branches and PRs (by author) … and builds (by the branch's owner)", but a branch with no PR and a build have no author in the payload today. The plan names no source for them. Checked with `grep -n "author\|committer\|owner" schema.ts`.
4. **medium: *Active sprint* duplicates the existing sprint filter.** `fleet.sprints` already holds only the Active sprints (`fleet.ts:6741`, and `:6274-6280` "`collectSprints` already returns the active sprints … Two Active sprints are permitted"). The Agents tab's multiselect lists exactly those (`AgentList.tsx:540`, `:893`). It filters rows through `sprintMembershipLookup` (`packages/board/src/app/lib/filters.ts:24`) and passes the release row through `rowIsSprintExempt` (`:329`). *Active sprint* on is the same filter with every option selected. A new `activeSprintScope(rows, sprints)` would be a second membership join. The open point about the union of several Active sprints is already answered by the multiselect. The existing join lives in the board app, not in the domain, so moving it is the domain-property change, and the plan does not name it.
5. **medium: `planningColumns(map, showReleased)` takes an input that the client does not have.** The server builds the columns with `phaseColumns(phaseMap)` (`packages/board/src/server/board.ts:2332`, `packages/domain/src/rules/workflow-phases.ts:221`), not `planPhases` (`:169`). The payload carries columns (`phase`, `leadership`, `accent`, `checklist`), not the map. *Show released* is per viewer in the URL, so the filter runs on the client over `board.columns`. The smaller form adds one flag to `PhaseColumn` (the column holds `plan:released`, as `checklist` marks `plan:delivered`) and adds a rule that drops that column unless the flag is on. `planPhases` has no caller outside its own test today.
6. **low: GitHub issues carry several assignees.** `--json assignees` returns an array. `Issue.assignee: string` keeps one, and the plan does not say which. A ticket assigned to the reader as a second assignee would then be hidden from the reader's inbox. Checked against `plot-host.sh:4732` and the plan's text.
7. **low: the shell-line gate refuses growth and does not accept a stated count.** `scripts/check-shell-lines.sh` reads "may shrink and may not grow … no override". The slice says "the PR states the net count", but it must hold the net count at 0 or below. That is reachable, because each new key fits on an existing `jq` projection line (`plot-host.sh:4734-4736`, `:4708-4715`).
8. **low: the tab rename reaches about 15 sites in `App.tsx`, not only `parseTab`.** `'agents'` is compared at `:349`, `:367`, `:378`, `:584`, `:613`, `:644` and `:974`. `revealBranch` writes `?tab=agents` (`:683-685`), and the labels are at `:1045-1047`. Nine files under `packages/board/test` use old `?tab=` URLs, and `collapse.ts:25` names `?tab=agents`. The redirect keeps them working. Tests that assert the URL after a switch will change.
9. **low: `PLOT_JIRA_JQL` overrides the Jira query** (`plot-host.sh:4684`). The plan's "the `inbox` rows, today's `assignee = currentUser()` read" does not hold for an adopter that sets it.
10. **info: these claims checked true.** `App.tsx:118` `type Tab` and `:123` `parseTab` with the `board` redirect. `App.tsx:633-638` `onTab` keeps every other parameter. `sections.ts:25` `GROUPS` with six groups. `AgentList.tsx:1123` (drafts in waiting-on-you), `:2367` (issues) and `:597` (sprint filter). `issue.ts:21-23` refuses the assignee and `:25-31` makes the status exception. `ports/tracker.ts:32-41` refuses a widened write. `plot-host.sh:4684` (`currentUser()`), `:4696` (`fields=summary,created,status`) and `:4732` (`--json number,title,url,createdAt`). The `bb issue list` row prints a reporter, not an assignee (`plot-host.sh:2132`). `person.ts:75` `parsePersonDirectory` already accepts `jira:x@y` as a spelling (`rest.join('=')`, lowercased). `mine-filter.ts:119` `readerFrom`. `sprint.ts:8` `Active`. `planPhases` exists (`workflow-phases.ts:169`). The first slice's `waits:` branch merged as #1623. `verificationRow` exists (`packages/domain/src/rules/auto-verify.ts:321`) and `AgentList.tsx` does not render it yet, which matches the plan's attribution to its sibling. `trackerGitHost` and `IssueIndexSchema` do not exist on main yet, as the plan expects.

## Amendments I require

- A1. In *The assignee* and in `feature/an-issue-names-its-assignee`, name `refreshIssues` (`fleet.ts:1473`, projection `:1536-1561`) and `IssueRowSchema` (`schema.ts:3368`, doc `:3321`) as the path that reaches *Waiting on you*. Either extend that path in this slice, or make the Delivery slice wait on the index slice that moves the board onto `trackerReads`, and state which. Strike "so a matched reader on a repository with no `Tracker` key also sees their tickets" until that path exists.
- A2. Build the ticket owner as an `OwnedRow` arm in `rules/ownership.ts` (`{ kind: 'ticket'; assignee; source }`) that uses the `jira:` lookup, instead of building a parallel `assigneeHandle` resolver. State that `waitingTickets` treats `unknown` as not-mine, while `isMine` keeps it, and give the reason.
- A3. Name the source of a branch's owner and a build's owner for *Only my work*. If there is none, narrow the Changelog and D9's wording for this plan to the rows that carry an owner, and record the rest as an open point.
- A4. Specify *Active sprint* as "select every sprint in `fleet.sprints`" over `sprintMembershipLookup` and `rowIsSprintExempt`, and move that join into the domain if it becomes a domain property. Drop `activeSprintScope` as a separate rule, or say why the existing join cannot serve.
- A5. Restate `planningColumns` over the payload's columns: add a flag on `PhaseColumn` for the column that holds `plan:released` and make the rule `planningColumns(columns, showReleased)`. Otherwise name how the client gets the map.
- A6. Say which GitHub assignee `Issue.assignee` keeps, or make it `assignees: string[]` with "the reader's when any resolves to the reader's handle".
- A7. Replace "the PR states the net count of `check-shell-lines.sh pr`" with "the slice adds no net shell lines".
