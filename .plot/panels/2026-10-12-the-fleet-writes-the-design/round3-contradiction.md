# Contradiction juror, round 3 — the-fleet-writes-the-design

Position: amend

The revision applies all seven round-2 amendments and D34, and every estate fact I checked holds on main at `1ad9a9f4f`. Through the contradiction lens the plan agrees with D3, D4, D10, D12 and D13, with the shipped spike and needs-design workflows, and with CLAUDE.md's host and ancestry rules. New text brings four contradictions that the plan must resolve before approval. First, with `Auto-design: false` (Changelog 7) `specStart` refuses `off` before it reads the restart mark, so `plot-design.mjs restart` cannot start a run in this repository, and the removal of *Commission design* leaves no route to a fleet spec here, against Open Point 3's default and Changelog 6. Second, a restart after a person closed a spec PR is defeated on the next pass: the old closed PR still answers `prState('idea/<slug>-spec')`, and the declined check writes the mark again. Third, the *Working* row for a going spec run has no builder: `the-board-has-three-tabs` builds a plan-level row for *Waiting on you* only. Fourth, `plot-design.mjs restart` writes the machine-local store that fleetd read-folds, which makes a second writer where the verify store has one.

## Findings

1. **high: the person's only control cannot start a spec run in this repository.** Evidence: plan line 52 orders `specStart`'s refusals with `off` first, and "a plan with a restart mark passes `declined`, `halted`, `stopped` and `waiting` once" — not `off`. Changelog 7 (line 22) declares `Auto-design: false` here. Open Point 3 (line 114) makes `plot-design.mjs restart <slug>` the person's control and removes *Commission design* with no replacement. So after this plan ships, no person and no fleet in this repository can start a spec agent. The verify run, which the plan copies, has a hand route outside the fleet (`/plot-deliver --verify`, the `hand-run` refusal at `packages/domain/src/rules/auto-verify.ts:169`); the spec run has none. D10 says the fleet commissions the spec; Open Point 13 in the story offers *Write the spec now* as the alternative. Checked by reading `verifyStart` (`auto-verify.ts:164-178`) and the plan's refusal list.
2. **medium: a restart after a closed spec PR does not start a run.** Evidence: the declined check (line 64) reads `host.prState('idea/<slug>-spec')` before the claim and writes `declined[slug]` on a closed or merged PR. The restart arm for a closed PR (line 96) deletes the ref and clears the mark, but the host still holds the closed PR for that head branch, and `prState` reads one PR "by number or by branch" (`packages/domain/src/ports/host.ts:155-161`). The next pass therefore reads the same closed PR and writes the mark again. Line 100 says the restart mark passes `declined` in `specStart`, but line 64 describes the fleet step as "writes the mark, starts nothing", so the two texts disagree on which one wins. Changelog 4 ("until a person restarts it") depends on this. The Acceptance (line 147) tests the restart arm's ref deletion and never that the next pass starts one run after a close.
3. **medium: the *Working* row has no builder in the sibling plan.** Evidence: the Board impact (line 25) and slice 4 (line 133) render a going run in *Working* "through the plan-level row kind that `the-board-has-three-tabs` builds on the `draftRows` path (`AgentList.tsx:475`, `:1123`)". `AgentList.tsx:1123` reads `const drafts = key === 'waiting-on-you' ? draftRows : []`, so that path renders only in *Waiting on you*. The sibling (`2026-10-12-the-board-has-three-tabs.md:49`) adds its entries "beside `drafts` for the `waiting-on-you` key", with the entry shape `{ plan, reason, log, restart, stopped }` and the halted mark as one line from `verification.halted`, not per row. The plan's `specRow` carries `fleetHalted` per row (line 53). So slice 4 must build a *Working* plan-level row that neither plan names, and the Acceptance browser test (line 149) asserts it.
4. **medium: the restart command is a second writer of fleetd's store.** Evidence: `plot-design.mjs restart` clears the failure record and the `declined` mark and writes a restart mark (lines 91-96), and fleetd consumes the mark at start (line 100), both on `.plot/state/auto-design-in-flight.json` (line 83). The verify store, which the plan extracts as the shared store, has one writer: every `updateVerifyState` caller is in `packages/fleet/src/shared/auto-verify.ts` (`:435`, `:444`, `:521`), and its doc guarantees only that "no other callback of this process writes between the read and the write" (`:185-191`). CLAUDE.md, *A Decision Reads The Index*, *One writer*: "`rename` makes each write atomic and not the read-fold-write sequence around it". A restart that lands between fleetd's read and its rename is lost, or fleetd's settlement is lost. The plan also does not say whether `declined` and the restart marks join the shared `RunStore` of line 57 or stay design-only.
5. **medium: a `work` ref with no PR and no local record is silent.** Evidence: the settlement table (lines 74-81) runs only for a run record on this machine, and the crash arm (line 87) covers `claim-only` refs only. A run on machine A whose agent pushed and whose machine then died before fleetd opened the PR leaves a `work` ref. On machine B, `designWork` answers `none` for `work` (line 51), no record exists, no row shows and no failure counts. Only `plot-design.mjs restart` repairs it (line 95), and nothing tells a person to run it. This is the class of round-2 amendment 1, narrowed to another machine or a lost store.
6. **low: the cost line understates host reads.** Evidence: line 102 counts "one host read (`prState`)" per run. `specStart` refuses `declined` and `host-unknown` before `halted`, `stopped`, `waiting`, `queue-unread`, `no-free-agent` and `starved` (line 52), so the `prState` reading is an input on every pass for every Design plan with an empty spec and an absent ref, also on the passes that then refuse for a full machine. D34's rationale is "adds no host calls"; the line should state the per-pass read, or the order should put the host read after the local refusals.
