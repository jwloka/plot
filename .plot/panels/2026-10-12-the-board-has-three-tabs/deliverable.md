# Deliverable juror: the-board-has-three-tabs

Position: amend

The design is sound and most estate claims hold on main at `316d3de0e`, but the plan is not yet buildable slice by slice. It has no `## Acceptance` section, so no Changelog claim has a named proving test, and no slice names a browser test for a state the reader sees. The Delivery slice carries three features in one line and asks for an owner fact that the row does not carry. The Design promises a failed-verification row in *Waiting on you* that nothing on main renders and no slice builds. Each gap has a small fix, so the position is amend, not reject.

## Findings

1. **high** — The plan has no `## Acceptance` section. Evidence: `docs/plans/2026-10-12-the-board-has-three-tabs.md` has the headings Status, Changelog, Motivation, Design, Slices and Notes only. The siblings `tickets-and-stories-have-lanes.md:222`, `the-fleet-verifies-what-it-delivered.md:224` and `design-work-proves-the-path.md:195` each have one. No Changelog claim (redirects, *Show released*, the assignee filter, the unmatched notice, *Active sprint*, *Only my work*) maps to a test that fails before and passes after. The only tests the slice lines name are the `People` unit tests. Checked with `grep -n "^## "` over the six 2026-10-12 plans.
2. **high** — The Delivery slice asks *Only my work* to filter branches "by author" and builds "by the branch's owner", but a branch row with no PR has no owner fact. Evidence: `packages/board/src/app/lib/agent-rows/mine-filter.ts:73-86` states that "a build of a branch is owned by whoever owns the branch, which no fact on the row says", and that the branch name is deliberately not consulted. `ownedFromRow` answers `{ kind: 'other' }` for every row without `pr`. A fleet agent cannot build this without inventing a fact source, and the plan names none. Checked by reading `mine-filter.ts:60-175`.
3. **high** — The Design says *Waiting on you* "lists the failed-verification row `verificationRow`, which `the-fleet-verifies-what-it-delivered` builds and renders in this section". On main the sibling slice merged (PR #1635), and the payload carries `verification` (`packages/board/src/contract/schema.ts:3973-3992`, `:4427`; `packages/board/src/server/fleet.ts:6779` `verificationPayload`), but nothing under `packages/board/src/app` reads `verification`, `VerificationStatus` or a restart command. The row is not rendered today, and no slice of this plan builds it. Checked with `grep -rn` over `packages/board/src/app` and `gh pr view 1635`.
4. **medium** — The Delivery slice is one line with three features: `waitingTickets` with its source-dependent notice, `activeSprintScope` with its toggle, and *Only my work* over five row kinds. Each has its own tests and its own render site in `AgentList.tsx` (2533 lines). One branch for all three makes one PR that is hard to review and one red test that blocks all three. Checked by reading slice line 81 of the plan.
5. **medium** — *Active sprint* duplicates the existing sprint multiselect. Evidence: `activeSprints` in `packages/board/src/server/fleet.ts:6341-6348` already keeps only sprints with `phase === 'Active'`, and `AgentList.tsx:540` uses that list as the multiselect's options. So the toggle equals "select every option", and `FleetSprintSchema` (`schema.ts:3913-3938`) has no state field for `activeSprintScope(rows, sprints)` to read. The plan does not say what happens when the toggle and the multiselect are both set. Open Point 12 (union of several Active sprints) is still unchecked, but the Design already answers union ("every sprint in state `Active`").
6. **medium** — GitHub's `assignees` is an array, and `Issue.assignee` is one string. The plan does not say which assignee the GitHub arm keeps, so an issue with two assignees can hide from the second one. Checked at `skills/plot/scripts/plot-host.sh:4732` (`--json number,title,url,createdAt`) and the Design's `assignee: string`.
7. **medium** — Two rules decide whether a ticket with no owner is shown. `waitingTickets` says "a ticket with no assignee is not the reader's", while `isMine` keeps every row whose owner is unknown (`mine-filter.ts:126-132`, `:159-161`). The Delivery slice applies both to tickets (the default filter and *Only my work* "by assignee") and does not say which wins. The Changelog also says *Only my work* "also filters ... PRs", but `rowsForReader` already filters PR rows by author (`mine-filter.ts:85-86`, `AgentList.tsx:649`), so no test of that claim can fail before.
8. **medium** — The plan does not name the module of `waitingTickets`, `activeSprintScope` or `planningColumns`. `boardForReader` and `rowsForReader` live in `packages/board/src/app/lib/agent-rows/`, not in `@plot-pm/domain`. The Design says "every view state is a domain property", and CLAUDE.md *The Layering Rule* asks for that. Also, the server builds the columns with `phaseColumns(phaseMap)` (`packages/board/src/server/board.ts:2332`), not `planPhases`; the plan does not say whether *Show released* drops the column on the server or in the client.
9. **low** — The People slice's three named parser tests pass before the change. `parsePersonDirectory` (`packages/domain/src/entities/person.ts:75-99`) already reads `jira:x` as one more spelling and already drops a spelling two handles claim. Only the `assigneeHandle` tests can fail before. The slice is a doc edit plus one function and could fold into the Delivery work.
10. **low** — The first slice waits on `feature/the-board-draws-the-declared-phases`, which merged as #1623 (`5d78df1e8`). The wait is satisfied, and the slice that uses `planPhases` (`feature/the-planning-tab-shows-design-to-testing`) carries no wait. Harmless now, but the dependency sits on the wrong line.
11. **low** — Motivation says "The Plans tab draws five phase columns". After #1623, `phaseColumns(DEFAULT_PHASE_MAP)` answers four, because Discovery holds no plan state (`packages/domain/src/rules/workflow-phases.ts:39-45`, `:221`). The other claims I checked hold: `App.tsx:118`, `:122` `parseTab`, `:633-638` `onTab`; `mine-filter.ts:119`, `:162`; `sections.ts:25`; `AgentList.tsx:597`, `:1123`, `:2367`; `issue.ts:21-31`; `tracker-shell.ts:46`, `:120` (path is `adapters/tracker/tracker-shell.ts`); `plot-host.sh:4684`, `:4696`, `:4732`; `sprint.ts:9`; `person.ts:75`.
12. **low** — "The docs that name the old tabs" is unbounded. 8 files outside `docs/plans` and `docs/stories` name *Agents tab*, *Plans tab*, *Stories tab* or a `?tab=` value, and 3 browser tests address a tab by its label. The slice line names neither set. The redirect keeps the 15+ test files that open `?tab=agents` working, which is good, but the slice names no test that proves the redirect.
13. **low** — The Approved sibling `tickets-and-stories-have-lanes` waits on two branches of this Draft plan (`tickets-and-stories-have-lanes.md:273`, `:277`). Its lanes slice and its Jira slice cannot start until this plan is approved and those branches merge.
