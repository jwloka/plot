# Estate juror, round 2: the-fleet-writes-the-design

Position: amend

The revision applies all eight of my round-1 amendments and all seven moderation amendments, and almost every name it cites now exists on `main` (553c4777b) at the line it gives. The spike slice is sound: the six filters, the scan verdict, the dispatch workflow, `/plot-implement` and the Brief command all admit the approved spike of a Design plan already. Three defects remain through the estate lens. First, the plan treats the *Waiting on you* and *Working* rows as existing machinery, but a plan-level row for a fleet-started run does not exist: #1635 deferred exactly that row to open issue #1640 because it needs a new row kind. Second, `auto-design.ts` "follows `auto-verify.ts`", a 593-line module, and the plan does not say which parts it shares and which it copies. Third, the dropped plan-PR-head arm rests on a false reading of the scan: the scan does read Design plans from idea branches, and the plan does not say what the spec reader answers for one. Each fix is small, so the position is amend.

Checked: `git show 275030213`, `gh issue view 1640`, grep of the board app.
2. **medium: the plan copies the auto-verify pass and does not say what it shares.** Evidence: `packages/fleet/src/shared/auto-verify.ts` is 593 lines: the state file reader and writer (`:152-222`), `verifyRunGoing` and `verifyingCount` (`:225-270`), the pass with settlement (`:417-514`), the start with `startBoardRun` (`:520-545`), and the status lines (`:547-593`). `packages/domain/src/rules/auto-verify.ts` holds `failuresSinceSuccess` and `verifyHalted` (`:73-85`), which are not specific to verify. `specStart` repeats six of `verifyStart`'s refusals in the same order (`:164-179`). 3. **medium: the rationale for dropping the plan-PR-head arm is false, and the reader's answer for that case is unstated.** Evidence: the Open Point says that "the fleet never sees a Design plan whose plan PR is open". The contradiction juror reported the same scan behaviour in round 1 (finding 12). Checked: read the scan header and the enumeration, and `readVerifyCandidatesWith`.
