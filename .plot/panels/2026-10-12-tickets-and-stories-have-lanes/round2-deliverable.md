## New defects

1. **Must change. The Changelog and one acceptance line contradict D22.** `plan:20` says the Delivery tab's *Waiting on you* "keeps showing only your tickets", and `plan:130` says that after the Jira scope slice it "still shows only the reader's Jira tickets". D22 (story `:97`) and `the-board-has-three-tabs:49` say an unmatched reader sees every ticket and a notice. Before `feature/the-lanes-read-the-whole-jira-project`, "every ticket" is the reader's own Jira tickets, because the JQL still holds `assignee = currentUser()` (`plot-host.sh:4684`). After it, "every ticket" is the whole project. So the slice at `plan:158` widens the inbox for every reader without a `jira:` spelling in `People`, and the Open Point at `plan:106` ("the Delivery inbox never widens before its filter exists") is true only for matched readers. Fix: state in the Changelog and in `plan:130` that a reader with a `jira:` spelling sees only their tickets, and a reader without one sees every project ticket and the D22 notice; name this as the upgrade note of the Jira scope slice.
2. **Open point. The assignee field has no named route into this plan's rows.** `the-board-has-three-tabs:71` reads `Issue.assignee` in `tracker-github.ts` and `tracker-jira.ts` only. This revision adds a third lister, `trackerGitHost` (`plan:44`), which serves this repository (no `Tracker` key) and every Bitbucket repository. All three connectors read through `plot-host.sh issue-list` (`tracker-shell.ts:145-148`), whose GitHub arm asks `--json number,title,url,createdAt` and whose Jira projection holds no assignee (`plot-host.sh:4710-4736`). If the assignee lands only in the two named connectors, every row from `trackerGitHost` has `assignee: ''`, and `waitingTickets` shows a matched reader no ticket on this repository. Also, slice 2's line (`plan:150`) does not name the conditional `IssueIndexSchema` field that `plan:121` assigns to it. Fix: name `trackerGitHost` and the `plot-host.sh` arms in `feature/an-issue-names-its-assignee`, and add "adds `assignee` if `feature/an-issue-names-its-assignee` merged first" to slice 2's line.
3. **Open point. `storyLane` passes a value `phaseOfStory` cannot take.** `plan:86-93` sends `standing` to the map and maps derived `archived` to Done. `StoryStanding` is `StoryStatus | 'archived'` (`transitions/story.ts:36`), and the grammar declares only `story:<status>` (`DESIGN-phases.md:69`), so no map can declare `archived`. `phaseOfStory(map, status)` (`the-phases-are-declared:48`) takes a status. Under a map that lists statuses without `story:*`, the rule "hidden for a status the map does not declare" hides every story whose plans are all released. Fix: state that derived `archived` reads as `done` for the map lookup, and add one table-row test with a non-wildcard map.
4. **Open point. The request count in acceptance does not match the plan's own measurement.** `plan:63` says one pass on this repository is 2 GitHub open pages and 1 closed page, and sets `PR_REQUESTS_PER_REFRESH.github` to 2; acceptance `plan:136` asserts `github: 2`. The table counts the open read as part of the existing 1 (`pr-refresh.ts:183-185`), so the pass spends 3 against a declared 2 once the open list passes 100 rows. Fix: either state that the table prices the call shape and the per-page records pay the rest, or count the pages.
