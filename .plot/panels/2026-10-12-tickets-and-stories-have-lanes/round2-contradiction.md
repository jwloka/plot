1. **`trackerGitHost` contradicts the tracker port's doc and `CLAUDE.md`, and the plan names neither edit.** Must change. `ports/tracker.ts:66-72` says *"A TRACKER IS NOT A GIT HOST"* and keeps `unaskable` for *"a repository that declared no tracker at all"*; `issueList` and `issueView` return *"`unaskable` where the repository declared no tracker"* (`ports/tracker.ts:103`, `:114`). `CLAUDE.md:381-384` says a repository with no tracker *"gets `trackerNone`, which answers `unaskable` on every operation"*. `trackerGitHost` (plan :44) answers `issueList` and `issueListClosed` for exactly that repository. The design is defensible — `trackerGithub` already reads the git host's own vendor through `plot-host.sh` (`tracker-github.ts:41-60`) — but the slice must rewrite the port doc paragraph, the two `@returns` lines and `CLAUDE.md:381-384`, and the plan's *Entity text* (:101) names only `issue.ts`. The plan also leaves `trackerGitHost.limit()` unspecified: `trackerReads` filters readings by the connector tag it is given (`tracker-shell.ts:160-166`), so the plan must name the tag (the git host's backend word) and state that the bucket it reports is the `host` connector's own, not a second budget.
2. **The D20 slice reads the whole Jira instance when no `Ticket prefixes` are declared, which the plan refuses for the closed read.** Must change. The project scope at `plot-host.sh:4675-4680` is optional: with no prefixes, `scope` is empty. Plan :69 drops `assignee = currentUser()` from the open read at `:4684` and keeps *"the project scope"*, so with no prefixes the open read becomes `resolution = EMPTY` over every project in the instance. Plan :54 refuses that shape for the closed read (*"an unscoped `resolved >=` query reads the whole instance"*), and D20 says *"the Jira tickets of the whole project"*, which presumes a declared project. The slice must keep the assignee clause, or exit 4 with the reason, when no prefixes are declared, and acceptance (:130) needs that case.
3. **The Changelog promises a narrow inbox that D22 widens for every unmatched Jira reader.** Must change. Changelog :20 says *"The Delivery tab's Waiting on you keeps showing only your tickets"*, acceptance :130 says the same, and Open Point :106 says *"the Delivery inbox never widens before its filter exists"*. D22 says an unmatched reader sees *"every ticket, as today"*; after `feature/the-lanes-read-the-whole-jira-project` lands, *every ticket* is the whole project, not today's assignee-scoped list. Every Jira adopter whose `People` key has no `jira:` spelling, which is every adopter at upgrade, gets a project-wide inbox with the D22 notice. The Changelog is the release note, so it must state the condition (*with a `jira:` spelling in `People`*) and the upgrade step, and acceptance must cover the unmatched reader and the notice (`the-board-has-three-tabs.md:49`).
4. **`PR_REQUESTS_PER_REFRESH.github: 2` disagrees with the plan's own measurement.** Open point. State which rule the number follows.

D7 and `DESIGN-phases.md` §5 say Done holds *"done stories that are not archived"*; the domain's word `archived` is the standing `derivedStanding` returns when every plan is released (`transitions/story.ts:402`), and plan :93 puts exactly that standing in Done.
