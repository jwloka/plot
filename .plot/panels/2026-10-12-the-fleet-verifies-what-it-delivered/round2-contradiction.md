## New defects

1. **The plan's own remedy path ends in a record nobody refreshes.** Line 95 sends a refuted plan that needs more slices back to Approved through `/plot-reject`. `/plot-reject` replaces the `Delivered:` line with `Rejected:` and touches no other record (`skills/plot-reject/SKILL.md:111-112`), so the `Verified:` line and `## Verification` survive. After the new slices merge and the plan is delivered again, line 99 forbids the fleet to run it ("never re-runs a plan that has a record"), and `verificationOf` still answers from the old pinned commit. The card keeps a stale badge until a person remembers `--verify`. Either `/plot-reject` moves the record into Notes, or `verificationOf` answers `unverified` when the record's commit is older than the current `Delivered:` commit.
2. **Tracer plans: the selector is wider than D18.** D18 says the fleet verifies every Delivered plan "in Testing" (STORY:93). D5 and DESIGN-phases.md:114 say a tracer plan never reads in Testing, and D14 and DESIGN-phases.md:190-191 let a tracer plan reach `State: Delivered`, alone or carried with its first dependent. Line 83 selects by `State: Delivered` only, so the fleet verifies a tracer plan, shows a *refuted* badge on a card in the Design column, and lists it on the checklist, because `Type:` keeps `feature` (D15). D12 lets the fleet read the `Tracer: yes` marker, so either outcome is expressible; the plan names neither.
3. **The CI-suite guard the juror paragraph relies on does not cover the verify worktree as described.** Line 71 says the controller gate refuses a `CI suites` command at a fleet desk. The gate fires only for `PLOT_UNATTENDED=1` in a linked worktree that holds `.plot-worker.pid` (`packages/board/src/server/entry/gate.ts:415-420`, `:460`, `:473`). The plan's detached `verify-<slug>` worktree (line 44) is not started by the worker loop, and the plan does not say it holds that marker. Without it, a juror may run `pnpm run test:e2e`, which CLAUDE.md *Testing* reserves for CI. Say that the run writes the marker, or name another guard.
4. **Minor: `--at <sha>` can renumber claims.** Line 42 says claims are read at the pinned commit "so a later edit of the Changelog does not renumber a run's claims". Line 99 reads them at the named commit and keeps "each issue number on its claim's line". A Changelog edit between the two commits moves a number onto a different claim. Match issue numbers by claim text, or refuse `--at` when the claim list differs.
5. **Minor: `PlanRecordWrite.field` is a closed union** of `Approved | Started | Delivered | Released` (`packages/domain/src/workflows/decision.ts:72-79`). Line 89 calls `Verified:` a `plan-record` write but no slice names the widening.
