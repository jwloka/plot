## New defects

- **The juror command source returns nothing at the pinned commit.** The plan says a juror runs "the commands `node skills/plot/scripts/board/plot-local-checks.mjs` prints for the files the plan changed". That tool takes no file list. It reads `refs.changedFiles('HEAD')` plus the working tree (`packages/board/src/server/entry/local-checks.ts:99-108`), and `changedFiles` is `git diff --name-only origin/<main>...HEAD` (`packages/domain/src/adapters/refs/refs-git.ts:309-317`). In a detached worktree at the delivery commit, HEAD is an ancestor of `origin/main`, so the diff is empty and the tool prints only the `**` gate lines. No plan-specific test runs, and `Evidence: executed` then certifies the generic gates. The plan must name the file list (the files of the plan's merge commits, read with `git show -m --first-parent` as `refs-git.ts`'s `commitFiles` does) and a way to hand it to the tool, such as a new argument in slice 3.
- **A re-verification writes a second `Verified:` line.** The plan writes `Verified:` as a `plan-record` (`workflows/decision.ts:72`), and says `/plot-deliver --verify` "replaces" it. `withRecord` fills an empty placeholder or appends after the last list item; it never replaces a filled line (`packages/domain/src/workflows/rendering.ts:66-96`). The template has no `Verified:` placeholder (`.plot/templates/plan.md:22-23` lists Approved and Started). So the first run appends, and every re-run appends again. In addition, `PlanRecordWrite.field` is the closed union `'Approved' | 'Started' | 'Delivered' | 'Released'` (`decision.ts:76`), which slice 1 or 2 must widen. The plan must name either a replace mode for `plan-record` or a separate write for the `Verified:` line.
- **The badge leaves the RC checklist during the RC round.** After `/plot-release rc` renames `vnext-checklist.md` to `v<version>-checklist.md`, the next verify run writes a new `vnext-checklist.md`, which sorts last again (`board.ts:423-424`). The Testing badge then counts the next cycle's checklist while the person tests the RC. The plan must say which file the badge reads between `rc` and the final release.
- **Minor: a plan released before its run is never verified, and `/plot-release` does not list it.** Measured on a sample of ten plans dated 2026-09-29, Delivered to Released took one to two days (all to v2.22.0 on 2026-10-01). The plan runs only `State: Delivered` plans, one run at a time, and `/plot-release` lists refuted plans only. An `unverified` plan in a release passes with no line. Listing `unverified` plans beside refuted ones costs one more filter on `verificationOf`.
