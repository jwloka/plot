# Contradiction juror — the-fleet-writes-the-design

Position: amend

The plan agrees with D3 and D10 on the main point: the fleet moves no plan into Design, approves nothing, and a person merges the spec. It also agrees with the shipped `needs-design` workflow on where a `Review: pr` spec commit goes. Through the contradiction lens, five problems need a change before approval. The spike-dispatch slice changes two of the six `approved` filters in `rules/auto-dispatch.ts`, and the four it leaves out compute the brief check, so a briefless spike gets dispatched. `designWork(plan)` claims to read the plan text only, but its `dispatch-spike` row needs merge and claim readings, and it duplicates `sliceVerdict`, which already admits the approved spike on main. The one-run record lives outside git and has no claim, which contradicts Manifesto Principle 1 and the fleet's ref-push claim model. The spec run has no opt-in key, unlike its shipped sibling `Auto-verify`. Its reuse of `Idea command` contradicts the "one capability, one key" rule that `implement-run.ts` states. Several Motivation and Notes sentences also describe work that has since merged as if it were still to come.

The comment at `auto-dispatch.ts:565-572` says that a second spelling of this rule is a second place for the functions to disagree, and this slice creates that disagreement.
